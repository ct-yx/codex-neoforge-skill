# NeoForge 1.21.1

本文件是基线速查，不替代目标项目的 Javadocs、MDK 或构建源码。官方版本入口：[1.21.1 getting started](https://docs.neoforged.net/docs/1.21.1/gettingstarted/)。

## 工具链与项目识别

- Minecraft：`1.21.1`。
- Java：64 位 Java 21；从 Gradle toolchain、`java -version` 和 CI 三处核对。
- 依赖：以项目使用的 ModDevGradle/NeoGradle 版本为准，不复制当前 26.1 插件配置。
- 元数据：`src/main/resources/META-INF/neoforge.mods.toml`。
- 常用目录：`src/main/java`、`src/main/resources`、`src/generated/resources`、`runs/client`、`runs/server`。
- 构建产物：`build/libs`。

## API 选择

| 领域 | 1.21.1 规则 |
| --- | --- |
| 标识符 | 仍以 `ResourceLocation` 体系为主；不要把 26.1 文档中的 `Identifier` 直接复制进来 |
| 注册 | 优先项目已有的 `DeferredRegister`/holder；挂到 mod event bus；不要同时维护第二个注册通道 |
| 事件 | 区分 `NeoForge.EVENT_BUS` 与 mod event bus；并行生命周期事件中的主线程工作交给 `enqueueWork` |
| 网络 | 以项目版本的 `RegisterPayloadHandlersEvent`、`PayloadRegistrar`、`CustomPacketPayload`、`StreamCodec` 和 `IPayloadContext` 签名为准；handler 线程和方向不可猜 |
| 逻辑侧 | 使用目标版本的 `Level#isClientSide()` 等价 API；服务端保存权威状态 |
| 物理侧 | 用 `Dist`/客户端事件隔离 client-only 类，专用服务端不能加载渲染类 |
| 持久数据 | 对方块实体、区块、实体、世界先核对 `AttachmentType`；ItemStack 优先 data components；动态接口再考虑 capabilities |
| AT/Mixin | 先找公开 API；确需使用时核对 ModDevGradle 声明、映射、描述符、注入侧和失败策略 |

## 运行和数据生成

1. 先执行 `./gradlew tasks --all`，不要假定存在 `runData`。
2. 按项目生成的 Data run configuration 和 `GatherDataEvent` 运行；当前文档线常见 `runClientData`/`runServerData`，但不能回填到 1.21.1 项目而不核实。
3. 运行 `runClient`、`runServer`，检查 `runs/client`、`runs/server` 中的 `logs/latest.log` 和 crash report。
4. 资源检查区分 `assets/<mod_id>` 与 `data/<mod_id>`；现代 NeoForge 可能合成 `pack.mcmeta`。
