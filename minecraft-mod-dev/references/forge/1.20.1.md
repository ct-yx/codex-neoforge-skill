# Forge 1.20.1

本文件只在基线验收后、用户明确指定 Forge 1.20.1 迁移时读取。官方文档分支：[MinecraftForge/Documentation `1.20.x`](https://github.com/MinecraftForge/Documentation/tree/1.20.x)。

## 工具链与项目结构

- Minecraft：`1.20.1`。
- Java：Java 17；以 Gradle toolchain、`java -version` 和 CI 为证据。
- 构建：Forge MDK + ForgeGradle；不要在 NeoForge 项目中添加 ForgeGradle。
- 元数据：`src/main/resources/META-INF/mods.toml`。
- 源码/资源：`src/main/java`、`src/main/resources`、`assets/<mod_id>`、`data/<mod_id>`。
- 运行目录通常为 `run`；产物为 `build/libs`，以项目配置为准。

## 核心 API 规则

### 依赖和联动 Mod

`mods.toml` 的 `[[dependencies.<modid>]]` 需要按目标版本填写 `modId`、`mandatory`、Maven `versionRange`、`ordering`（`BEFORE`/`AFTER`/`NONE`）和物理 `side`（`CLIENT`/`SERVER`/`BOTH`）。这些字段只控制加载前的依赖条件；联动 adapter 仍须验证目标 Mod 的注册、事件、网络、数据和存档运行逻辑。

### 入口和注册

入口使用 `@Mod`。典型的 mod event bus 连接形式是：

```java
IEventBus modBus = FMLJavaModLoadingContext.get().getModEventBus();
ITEMS.register(modBus);
```

注册优先使用 `DeferredRegister` + `RegistryObject`；普通游戏事件使用 `MinecraftForge.EVENT_BUS` 和 `@SubscribeEvent`/`@EventBusSubscriber`。按项目已有写法决定实例或静态订阅。

### 网络

Forge 1.20.1 常用 `SimpleChannel`、`NetworkRegistry.newSimpleChannel` 和 `registerMessage`。网络 handler 默认运行在网络线程，必须按目标签名执行：

```java
ctx.get().enqueueWork(() -> handleOnMainThread(message));
ctx.get().setPacketHandled(true);
```

服务端重新验证客户端提供的坐标、权限、区块和状态；读取区块前检查 `Level#hasChunkAt` 等目标 API。

### 侧、数据生成和生命周期

- 逻辑侧使用 `Level#isClientSide`；物理侧使用 `FMLEnvironment#dist`/`DistExecutor`。
- 客户端类由 Dist 隔离，专用服务端不能加载渲染、屏幕或键位类。
- 数据生成使用 `GatherDataEvent`，常见命令为 `runData`；先查看 `./gradlew tasks`。
- 构建默认使用 `./gradlew build`，运行 `runClient`/`runServer`，首次专用服务器需处理 `eula.txt`。

## 与 NeoForge 基线的明确差异

```text
Java 17          != Java 21
mods.toml        != neoforge.mods.toml
SimpleChannel    != 1.21.1 payload/StreamCodec 体系
runData          != 未经核对的 NeoForge 数据任务
ForgeGradle      != NeoForge ModDevGradle/NeoGradle
```
